Manage all portfolio content through structured data files in the `src/data/` directory. This approach keeps content separate from components for easy maintenance.

## Skills management

Skills are defined in `src/data/constants.ts` using a strongly-typed system with TypeScript enums and interfaces.

### Skill structure

Each skill includes:

```typescript
type Skill = {
  id: number;
  name: string;
  label: string;
  shortDescription: string;
  color: string;
  icon: string;
};
```

### Adding a new skill

1. Add the skill name to the `SkillNames` enum:

```typescript
export enum SkillNames {
  AWS = "aws",
  DOCKER = "docker",
  REACT = "react",
  // Add your skill
  PYTHON = "python",
}
```

2. Define the skill in the `SKILLS` record:

```typescript
export const SKILLS: Record<SkillNames, Skill> = {
  [SkillNames.PYTHON]: {
    id: 25,
    name: "python",
    label: "Python",
    shortDescription: "Building awesome things with Python!",
    color: "#3776ab",
    icon: "https://cdn.jsdelivr.net/gh/devicons/devicon/icons/python/python-original.svg",
  },
  // ... other skills
};
```

### Skill properties explained

- `id`: Unique identifier (increment from last skill)
- `name`: Lowercase identifier for URL slugs
- `label`: Display name shown in the UI
- `shortDescription`: Brief, engaging description (supports personality!)
- `color`: Hex color code for the skill badge
- `icon`: URL to the skill icon (devicon CDN recommended)

### Icon resources

The portfolio uses [Devicon](https://devicon.dev/) for technology icons:

```typescript
icon: "https://cdn.jsdelivr.net/gh/devicons/devicon/icons/{tech}/{tech}-original.svg"
```

Replace `{tech}` with the technology name (lowercase).

## Projects data

While the source doesn't include a projects file in the provided code, projects typically follow a similar pattern:

```typescript
export type Project = {
  id: number;
  title: string;
  description: string;
  technologies: SkillNames[];
  image: string;
  liveUrl?: string;
  githubUrl?: string;
  featured: boolean;
};

export const PROJECTS: Project[] = [
  {
    id: 1,
    title: "Your Project",
    description: "A detailed description of what you built.",
    technologies: [SkillNames.REACT, SkillNames.NEXTJS],
    image: "/assets/projects/project-1.png",
    liveUrl: "https://project.com",
    githubUrl: "https://github.com/you/project",
    featured: true,
  },
];
```

## Best practices

### Skill icons

- Use consistent icon sources (Devicon recommended)
- Ensure icons work in both light and dark modes
- Test icon URLs before deploying

### Descriptions

- Keep skill descriptions concise (under 100 characters)
- Maintain consistent tone across all skills
- Consider accessibility when using emojis

### Data organization

- Keep skills ordered by category or importance
- Use meaningful ID numbers (avoid gaps)
- Group related technologies together

## TypeScript benefits

The typed skill system provides:

- Autocomplete for skill names
- Type safety when referencing skills
- Compile-time error checking
- Better refactoring support

```typescript
// TypeScript ensures you use valid skill names
const mySkills: SkillNames[] = [
  SkillNames.REACT,
  SkillNames.TYPESCRIPT,
  // SkillNames.INVALID // ❌ Error: doesn't exist
];
```
